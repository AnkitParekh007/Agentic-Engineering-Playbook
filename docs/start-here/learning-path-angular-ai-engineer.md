# Learning Path: Angular AI Engineer

This path is for developers who want to build Angular-based copilots, operator tools, and enterprise-facing AI user experiences.

## Core outcome

By the end of this path, you should be able to build an Angular copilot surface that connects to retrieval, orchestration, tools, approvals, and observability layers.

## Phase 1: Learn the runtime boundary

Study:

- provider abstractions
- structured outputs
- streaming basics
- stable schemas between UI and backend

Start with:

- [LLM Foundations Overview](../llm-foundations/overview.md)
- [Project 01: AI Provider Gateway](../llm-foundations/project-ai-provider-gateway.md)

## Phase 2: Learn grounded AI product behavior

Study:

- chunking and retrieval
- citations
- answer quality
- eval-driven iteration

Build:

- [Project 02: Enterprise RAG Copilot](../rag-systems/project-enterprise-rag-copilot.md)

## Phase 3: Learn orchestration and approvals

Study:

- planning
- state transitions
- tool routing
- retries
- human approval patterns

Build:

- [Project 03: Agent Workflow Orchestrator](../agent-frameworks/project-langgraph-orchestrator.md)

## Phase 4: Learn tool and MCP-adjacent architecture

Study:

- safe tool design
- read-only resources
- audit logging
- enterprise boundary control

Build:

- [Project 04: MCP Enterprise Toolkit](../tool-calling-mcp/project-mcp-enterprise-toolkit.md)

## Phase 5: Build the Angular operator experience

Focus here:

- visible agent activity
- session management
- approval UI
- trace-friendly layouts
- serious copilot UX instead of generic chat skins

Build:

- [Project 05: Angular Agentic Copilot](../agentic-ui/project-angular-agentic-copilot.md)
- [Angular Copilot UX Patterns](../agentic-ui/angular-copilot-ux-patterns.md)

## Phase 6: Add browser and QA workflows

Study:

- evidence capture
- dry-run policy
- browser task safety
- operator review flows

Build:

- [Project 06: QA Browser Agent](../agentic-ui/project-qa-browser-agent.md)

## Portfolio milestone

You are in strong shape when you can publicly show:

- one Angular copilot UI
- one retrieval-backed assistant
- one approval-heavy orchestration flow
- one tool layer with auditability
- one browser or QA workflow with visible evidence output
