# Contributor Roadmap

## Goal

Make it easy for contributors to find useful work, start small, and grow into substantial ownership over time.

## Stage 1: First contribution

Good starting tasks:

- fix a docs gap
- improve a diagram
- tighten README copy
- improve one project README
- add one practical exercise to a chapter

## Stage 2: Content contributor

Next-level tasks:

- contribute a full chapter
- add a project upgrade guide
- improve one learning path
- write a comparison page for a framework or architecture pattern

## Stage 3: Project contributor

Higher-trust tasks:

- improve one starter project validation workflow
- add a safer configuration pattern
- improve smoke or eval coverage
- expand project docs with architecture notes

## Stage 4: Community contributor

Growth tasks:

- maintain weekly challenge prompts
- curate good first issues
- improve issue templates
- help review incoming content proposals

## What maintainers should keep doing

- keep issues scoped and beginner-friendly when possible
- connect docs work to project outcomes
- preserve a practical, no-hype tone
- avoid fake growth narratives
- prefer visible proof of work over vague roadmap claims
